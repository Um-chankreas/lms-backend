# Data we collect and why

One row per kind of data, with the purpose it is used for. Most students are under 18, so a new field needs a row here before it ships. Anything not listed is not collected.

Everything below sits in tables with row-level security on and **no policies**. Only lms-backend (service-role key) can read or write them, and each route decides who may see what. Students never hold a database key.

| Data | Where it is stored | Purpose |
|---|---|---|
| Name, email or phone, password (hashed), avatar, bio | `users` | Sign in, show the student to their teachers and (name, avatar) friends and the leaderboard |
| XP, lesson, unit and quiz results | `xp_events`, `*_completions`, `quiz_submissions` | Learning path, progress, teacher reports |
| School, province | `student_private` | Help teachers know their students. Never shown on the leaderboard or friend lists |
| Telegram chat id, user id, username, first name, phone (only if the student shares it with the bot) | `student_private` | Class reminders by Telegram. Teachers see the username and phone only if the student's `telegram_visibility` allows it |
| Push token | `push_tokens` | Push notifications |
| **Phone model** | `device_sessions.model` | **Analytics (which phone models and app versions students use):** decide which phones and OS versions to test on and support |
| **OS version** | `device_sessions.os_version` | **Analytics (which phone models and app versions students use):** same as above |
| **App version and build** | `device_sessions.app_version`, `app_build` | **Analytics (which phone models and app versions students use):** know how many students still run an old version before raising the minimum version. Also decides who sees the "update" prompts |
| Random install id | `device_sessions.device_id` | Count how many devices one account uses. Generated by the app on first launch, not linked to the hardware, and a reinstall gets a new one |
| Tour finished time | `student_private.tour_completed_at` | Show the guided tour once per account, not again on a new phone |

## Analytics (which phone models and app versions students use)

- **What:** phone model, OS version, app version and build, platform (Android or iOS), the random install id, and when the device was first and last seen.
- **Not collected:** advertising id, IMEI, serial number, IP address, location, contacts, or anything about other apps.
- **When it is sent:** each time the app starts with a signed-in account, after sign-in, and when the app returns to the foreground (at most every 6 hours).
- **Who sees it:** only admins and super admins, on the dashboard "Devices" card, as **totals** (counts per model, per app version, devices per user). The raw rows are not exposed by any API. Phone models used by fewer than 3 people are grouped as "Other" so a rare phone cannot point at one student.
- **Deleted with the account:** `device_sessions` rows are removed when the account is purged (`on delete cascade`).
- **Not used for:** ads, profiling, or anything outside the purpose above.
